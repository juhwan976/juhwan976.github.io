## Brittany Chiang (brittanychiang.com)

### 관찰한 특징

- 다크 네이비 단색 배경, 콘텐츠 최대 너비 1280px 중앙 정렬 (1920에서 좌우 각 320px 여백).
- 2컬럼 구조. 왼쪽 컬럼은 화면에 고정: 이름(대형) → 직무(Frontend Engineer) → 한 줄 소개("I build accessible, pixel-perfect experiences for the web.") → 섹션 내비(ABOUT / EXPERIENCE / PROJECTS) → 소셜 아이콘. 오른쪽 컬럼만 스크롤.
- 섹션 내비는 현재 보고 있는 섹션에 맞춰 선이 길어지고 글자가 밝아짐. 별도 헤더 없음. 페이지 전체가 원페이지 이력서 구조.
- About은 문단 3개. 현재 소속(Klaviyo)이 첫 문단에 굵게 링크로 들어감.
- Experience 항목 구조: 왼쪽에 기간(소형 대문자, "2018 — 2024"), 오른쪽에 `직책 · 회사 ↗` 링크 → 같은 회사 내 이전 직책들이 아래에 회색으로 나열됨(Lead Engineer → Senior Engineer → Engineer, 승진 이력을 한 항목 안에 표현) → 3~6줄 설명 → 기술 pill 태그.
- Experience 마지막에 "View Full Résumé ↗" 텍스트 링크 하나만 배치.
- Projects는 좌측 작은 썸네일 + 우측 제목/설명/스타·설치수 지표 + 태그. 마지막에 "View Full Project Archive →".
- hover: 카드 영역에 옅은 배경 하이라이트, 제목이 accent 색으로 변함. 페이지 전체에 마우스 따라다니는 옅은 radial glow.
- 모바일(390): 좌측 고정 컬럼이 해제되고 일반 상단 블록이 됨. 섹션 내비 사라지고 ABOUT/EXPERIENCE 소형 대문자 sticky 헤더로 대체. 콘텐츠·정보량은 데스크톱과 동일.
- 화면 전환·스크롤 연출 없음. 스크롤은 순수 네이티브.

### 참고할 요소

- Experience 항목의 정보 구조: 기간(좌) + 역할·소속(우) + 역할 변화 나열 + 짧은 설명 + 기술 태그. 한 회사 안에서 직책이 확장된 과정을 한 항목에 쌓아 보여주는 방식 → 아뮤즈에서 역할이 확장된 Career 섹션에 그대로 유효.
- 섹션 내비(ABOUT/WORK/CAREER/…)가 현재 위치를 표시하는 좌측 고정 구조 → 채용 담당자가 원하는 섹션으로 즉시 이동 가능.
- "View Full Résumé ↗"를 Experience 끝에 두는 배치.
- 모바일에서 레이아웃만 해제하고 정보는 하나도 줄이지 않는 태도.

### 참고하지 않을 요소

- 1280px 중앙 컨테이너 — 이번 목표는 1600~1800px까지 쓰는 넓은 레이아웃.
- 프로젝트를 작은 썸네일 리스트로 표현하는 방식 — Selected Work는 큰 미디어 중심으로 감.
- 기술 pill 태그의 개수(항목당 5~9개) — 과다. 최대 4개로 제한.

## Emil Kowalski (emilkowal.ski)

### 관찰한 특징

- 라이트 배경, 본문 컬럼 644px. 1440에서도 콘텐츠는 이 폭을 유지(화면 좌측 1/4 지점에 배치).
- 페이지 전체가 리스트 4개: Today / Projects / Writing / More. 총 스크롤 약 2400px.
- 자기소개("Today")는 문장 2개 + "Previously, I worked on the design team at Vercel." 한 줄. 끝.
- 프로젝트는 `이름(검정) + 한 줄 설명(회색)`만. 이미지·태그·지표 없음. 이름이 링크.
- 제목과 본문의 크기 차이가 거의 없음. 위계는 색(검정 vs 회색)과 여백으로만 만듦.
- 섹션 라벨(Today, Projects)은 본문과 같은 크기. 여백이 섹션 구분의 전부.
- 모션 없음. hover 시 링크 색만 미세하게 변함.
- 모바일: 동일한 단일 컬럼이 그대로 좁아짐. 생략되는 요소 없음.

### 참고할 요소

- 자기소개의 길이 기준: "지금 무엇을 하는가" 2문장 + "이전에는" 1문장. About 섹션의 확정 문구 분량과 정확히 맞는 모델.
- 색(밝음/어두움)과 여백만으로 위계를 만드는 타이포그래피 — 프로젝트 메타 정보(기간·팀·기술)에 적용.
- 프로젝트 상세로 들어가는 진입점을 "이름 + 한 줄"로 최소화하는 절제.

### 참고하지 않을 요소

- 644px 전폭 레이아웃 — 본문 폭 기준으로만 참고하고, 전체 레이아웃은 넓게 사용.
- 이미지·지표가 전혀 없는 구성 — 이 포트폴리오는 실제 화면·성과 수치가 신뢰의 핵심이므로 미디어를 유지.
- 라이트 테마.

## Rauno Freiberg (rauno.me)

### 관찰한 특징

- 현재 사이트는 세로 스크롤이 가로 카드 덱을 구동하는 갤러리 구조. 상단에 필름 스트립 모양의 진행 인디케이터가 있고, 카드 하나가 지날 때마다 한 칸씩 이동.
- 카드 = 흰 패널 하나. 각 패널에 거대한 요소 하나만: 소개 문장(노란 원과 겹침), "Devouring Details"의 거대한 D + 오렌지 원, 파란 픽셀 커서 아이콘, 잘려나간 초대형 "Projects" 타이포, 손글씨 "Rauno's Field Notes", 연도·링크 4개(Twitter/2023/Email/2022/GitHub)를 네 모서리에 배치한 Contact 카드.
- 마지막 카드는 노란 배경에 원칙 선언: "Make it fast. Make it beautiful. Make it consistent. Make it carefully. Make it timeless. Make it soulful. Make it."  — 원칙 하나가 한 줄, 설명 없음.
- 자기소개는 문장 1개: "Rauno Freiberg is an Estonian interaction designer working with Vercel and Devouring Details."
- 텍스트 총량이 다섯 사이트 중 가장 적음. 대신 커서 중앙의 십자(+) 표시, 카드가 스크롤 방향으로 미세하게 밀리는 관성 등 상호작용의 질감이 개성을 만듦.
- 모바일: 동일한 가로 카드 덱이 작은 화면에 맞게 축소. 카드 비율 유지.

### 참고할 요소

- 원칙을 "선언 한 줄"로 표현하는 방식 — Development Principles 4개 문구에 그대로 적용. 설명은 최대 두 줄.
- 화면 하나에 요소 하나만 두는 배짱 — Principles를 4열 카드가 아니라 한 항목씩 넓게 배치하는 근거.
- 작은 인터랙션 하나(진행 인디케이터, 미세한 관성)가 사이트 전체의 인상을 만든다는 점 — 모션 총량을 줄이고 한두 곳에 완성도를 집중.

### 참고하지 않을 요소

- 가로 스크롤 갤러리 구조 자체 — 스크롤을 강제로 제어하는 효과라 이번 원칙(사용 금지 목록)과 충돌. 채용 담당자의 정보 탐색에도 불리.
- 프로젝트 설명·성과가 전혀 없는 구성 — 경력직 포트폴리오 목적과 맞지 않음.

## Max Milkin (maxmilkin.com)

### 관찰한 특징

- 풀스크린 3D 히어로: 세이지 그린 안개 배경에 실사 질감의 바위 하나, 그 위에 소형 대문자 모토("MINIMALISM IS NOT EMPTINESS. IT'S ESSENCE."). 마우스에 따라 카메라·바위가 미세하게 반응. 스크롤하면 문장이 바뀌며 서명이 나타남.
- 섹션마다 배경이 통째로 반전됨: 세이지(히어로) → 블랙(About) → 세이지(Awards) → 블랙(Works·Expertise) → 세이지(Contact·푸터). 섹션 전환 자체가 가장 큰 모션.
- About: 화면을 덮는 초대형 타이포("FUNDAMENTALS OF WEB DEVELOPMENT")가 배경처럼 깔리고 중앙에 인물 사진. 글자가 스크램블/분해되는 효과가 계속 동작 — 문장을 읽기 어려움.
- Awards: 좌측 정렬 제목 + `2X | AWWWARDS | SITE OF THE DAY` 형식의 얇은 구분선 테이블. 수상 내역이 즉시 읽힘. 배경에 산 능선 실루엣.
- Works: 중앙에 떠 있는 3D 바위, 주변 네 방향에 밑줄 프로젝트명. hover하면 해당 프로젝트의 스크린샷 프리뷰가 중앙에 나타남. 클릭 전에는 프로젝트 정보가 전혀 없음.
- Contact: 예산 선택 버튼(5K-10K 등)이 있는 문의 폼. 푸터는 초대형 "MAX MILKIN" + "CREATIVE FRONTEND DEVELOPER" 타이포.
- 모바일: 네이티브 스크롤 대신 가상 스크롤(body 높이가 화면 높이로 고정). 3D는 유지되고 내비는 햄버거로. 스크롤이 무겁게 느껴짐.
- 채용 관점에서 경력·기간·역할 정보는 사이트 어디에도 없음. 클라이언트 영업용 쇼릴에 가까움.

### 참고할 요소

- 히어로의 "화면 전체를 쓰는 단일 오브젝트 + 짧은 문장 + 약한 마우스 반응" 구성 — 현재 HeroScene(Three.js)을 유지·절제하는 기준.
- 섹션 배경 톤 변화로 전환을 알리는 방식 — 물류 시뮬레이터(3D 프로젝트) 구간에만 제한 적용.
- Awards 테이블의 얇은 구분선 리스트 형식 — Career의 기간·역할 표기에 응용 가능.
- 초대형 푸터 타이포 — Contact 마무리에 이름·직무를 크게 박는 방식.

### 참고하지 않을 요소

- 읽는 동안 계속 움직이는 스크램블 타이포 — 내용 전달을 직접 방해함(직접 확인).
- hover해야만 프로젝트를 볼 수 있는 Works 구조 — 발견에 의존하는 탐색은 금지 목록에 해당.
- 가상 스크롤(모바일 포함) — prefers-reduced-motion·접근성·체감 성능 모두 불리.
- 예산 문의 폼, 수상 개수 중심의 어필 — 프리랜서 영업 문맥. 채용 문맥과 다름.

## Michael Pumo (michaelpumo.com)

### 관찰한 특징

- 히어로는 50/50 분할: 좌측 블랙 패널에 "Open for new projects" 상태 배지 + 3줄 헤드라인 + 2줄 소개 + CTA 버튼 + 하단에 GitHub/LinkedIn/이력서 링크("Download my resume (PDF 248kb)" — 파일 크기까지 표기). 우측은 본인 사진 풀블리드.
- 전체 페이지 약 14,400px로 다섯 사이트 중 가장 김. 다크 베이스에 섹션 라벨(Strategy 등) + 본문 확대 타이포. 스크롤하면 문장이 회색→흰색으로 채워지는 텍스트 필 효과.
- 프로젝트 목록: 프로젝트 1개 = 화면 절반 높이의 가로 밴드 1개. 좌측에 프로젝트명(오렌지빛 코랄 색) + 2~3문장 설명(무엇인지 한 줄 + "Built using Nuxt, Storyblok, TypeScript and Tailwind" 형태로 기술을 문장에 녹임) + "Open project" 버튼. 우측에 대형 이미지. 프로젝트들이 카드처럼 겹치며 쌓이는 스택 효과.
- 1920에서 콘텐츠 최대 약 1660px — 화면을 거의 가득 씀. 여백은 화면 크기에 비례.
- 기술 badge·수치·수상 없음. 실제 클라이언트 사이트 이미지가 신뢰의 전부.
- FAQ 5개(01~05 번호 리스트), 마지막은 2줄 문장 + 이메일 주소만으로 마무리. 하단에 사이트 설정 카드(서체/팔레트/사운드) 이스터에그.
- 모바일: 히어로 사진이 빠지고 텍스트 패널만 남음. 프로젝트 밴드는 세로 스택(텍스트 → 이미지). 이력서 링크는 유지.

### 참고할 요소

- 프로젝트 1개 = 넓은 밴드 1개 (텍스트 40 : 이미지 60) 구성 — Selected Work의 기본 레이아웃.
- 기술 스택을 badge 나열 대신 문장·메타 줄에 녹이는 방식.
- 이력서 링크를 히어로와 푸터 양쪽에 두고, PDF 용량까지 표기하는 실용적 디테일.
- 1600px+까지 화면을 쓰되 여백을 비례로 유지하는 와이드 레이아웃.
- 마지막 Contact를 "2줄 문장 + 이메일"로 끝내는 담백함.

### 참고하지 않을 요소

- 14,000px가 넘는 페이지 길이와 문장 단위 텍스트 필 효과의 반복 — 읽기 속도를 스크롤이 결정하게 됨.
- 프로젝트 카드 스택(겹침) 효과 — 이미지가 가려지는 구간이 생김. 이번엔 mask reveal 정도로 절제.
- FAQ, 예산·프로세스 등 프리랜서 영업 섹션.
